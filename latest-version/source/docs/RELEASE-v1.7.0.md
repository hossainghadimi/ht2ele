# HTML2Elementor 1.7.0 — تصویر طرح → Qwen-VL → المنتور قابل‌ویرایش

## اجرای بسته

برای Windows 10/11 x64. ZIP را **کامل استخراج** کنید؛ پوشه‌های `runtime`، `engine` و `ai` کنار `HTML2Elementor.exe` بمانند. نسخهٔ قبلی را ببندید و EXE را اجرا کنید. رابط فارسی در مرورگر باز می‌شود. برنامه امضای دیجیتال ندارد؛ پیش از تأیید هشدار ویندوز، منبع و هش بسته را بررسی کنید.

Python 3.12.10، Pillow 11.3.0، micrograd 0.1.0، موتور CPU از llama.cpp b11095 و کتابخانهٔ بینایی `mtmd.dll` داخل بسته‌اند. نصب Python، pip، PyTorch یا CUDA برای حالت CPU لازم نیست. **وزن مدل و موتور CUDA داخل این ZIP سبک نیستند.** پس از دریافت مدل، تحلیل روی دستگاه و بدون ارسال تصویر به اینترنت انجام می‌شود. فایل‌های بیرونی HTML، مانند عکس و فونت اینترنتی، برای اجرای آفلاین باید جداگانه محلی شوند.

این انتشار فقط ZIP جدید ۱.۷.۰ را می‌سازد؛ ZIP نسخه‌های قبلی که حذف شده‌اند بازسازی نمی‌شوند. فایل ZIP را می‌توانید در پوشهٔ `versions` کنار پوشهٔ استخراج‌شده نگه دارید تا دکمهٔ دانلود داخل برنامه نیز آن را پیدا کند.

## مدل پیشنهادی برای RTX 3050 با ۸ گیگابایت VRAM

**Qwen3-VL-4B-Instruct، زبان Q4_K_M + projector Q8_0** از مخزن رسمی یکسان:

- [کارت مدل رسمی و مجوز](https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct-GGUF)
- [دانلود Qwen3VL-4B-Instruct-Q4_K_M.gguf](https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct-GGUF/resolve/main/Qwen3VL-4B-Instruct-Q4_K_M.gguf?download=true) — 2,497,281,664 بایت.
- [دانلود mmproj-Qwen3VL-4B-Instruct-Q8_0.gguf](https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct-GGUF/resolve/main/mmproj-Qwen3VL-4B-Instruct-Q8_0.gguf?download=true) — 453,974,304 بایت.

مجموع فایل‌ها حدود **۲٫۹۵ GB** است؛ این عدد مصرف RAM یا VRAM نیست. مدل متنی قبلی Qwen به‌تنهایی تصویر نمی‌خواند. فایل projector هم‌خانواده و درست لازم است. ترکیب Q4 زبان و Q8 projector در راهنمای رسمی این مخزن مجاز است.

این انتخاب نقطهٔ شروع کم‌حجم‌تری نسبت به مدل‌های بزرگ‌تر است، نه تضمین جا شدن همهٔ پردازش در VRAM یا تضمین سرعت و دقت. RAM سیستم شما هنوز مشخص نیست. وزن‌ها، کش متن، encoder تصویر، buffers و برنامهٔ میزبان همگی حافظه می‌خواهند. وضوح تصویر، تعداد توکن و برنامه‌های دیگر بر مصرف اثر می‌گذارند. برای متن ریز و صفحات شلوغ، تصویر هر سکشن را جدا بدهید. برنامه فعلاً در CUDA درخواست offload برای **۲۰ لایه** می‌دهد؛ همهٔ لایه‌ها الزاماً روی GPU نیستند.

هش SHA-256 فایل‌های پیشنهادشده، مطابق metadata مخزن هنگام آماده‌سازی این نسخه:

```text
Qwen3VL-4B-Instruct-Q4_K_M.gguf
66358cb18bb6b3b1b6675aa412c7a88ef01d228f481184d13668e5201c730a0a

mmproj-Qwen3VL-4B-Instruct-Q8_0.gguf

```

این دو فایل بزرگ برای این تست دانلود نشده‌اند؛ هش‌ها حاصل محاسبهٔ محلی روی دانلود کامل نیستند. اگر مخزن تغییر کند، metadata نسخهٔ دانلودشده را نیز بررسی کنید.

### فعال‌کردن RTX / CUDA، اختیاری

CPU داخل بسته آماده است و معمولاً کندتر خواهد بود. برای GPU، درایور NVIDIA سازگار لازم است. هر دو بستهٔ هم‌نسخهٔ زیر را از انتشار رسمی b11095 بگیرید و فایل‌های لازم آن‌ها را کنار هم داخل پوشهٔ `engine-cuda` کنار EXE استخراج کنید؛ `llama-server.exe` باید مستقیم داخل این پوشه باشد، نه داخل یک زیرپوشهٔ اضافی:

- [موتور Windows x64 CUDA 12.4](https://github.com/ggml-org/llama.cpp/releases/download/b11095/llama-b11095-bin-win-cuda-12.4-x64.zip)
- [DLLهای CUDA 12.4 همان انتشار](https://github.com/ggml-org/llama.cpp/releases/download/b11095/cudart-llama-bin-win-cuda-12.4-x64.zip)
- [صفحهٔ انتشار رسمی](https://github.com/ggml-org/llama.cpp/releases/tag/b11095)

حجم مجموع این دو ZIP حدود ۶۴۵ MB است. بستهٔ ARM64 را برای ویندوز x64 انتخاب نکنید و DLLهای نسخه‌های مختلف را مخلوط نکنید. سپس در پنل، «RTX / CUDA» را انتخاب کنید. اگر موتور پیدا نشد یا بارگذاری متوقف شد، لاگ کارگاه AI را ببینید؛ ابتدا CPU را امتحان کنید. اجرای Windows/CUDA روی RTX 3050 در این محیط تست نشده است.

## گردش کار جدید

1. تب **«تصویر → ویجت با Qwen»** را باز کنید؛ بارگذاری تصویر از ورودی اصلی نیز این تب را باز می‌کند.
2. مسیر کامل محلی دو فایل مدل و mmproj را وارد و جفت مدل را ثبت کنید. برنامه آن‌ها را کپی یا خودکار دانلود نمی‌کند. مدل و projector باید از همان خانواده باشند.
3. تصویر، مدل بینایی، CPU یا CUDA، میزان جزئیات و جهت صفحه را انتخاب کنید.
4. **«تحلیل تصویر و ساخت ویجت‌ها»** را بزنید. برنامه مدل را راه‌اندازی می‌کند، تصویر واقعی را به API چندوجهی می‌فرستد و پیشرفت بخش‌ها را نشان می‌دهد.
5. پاسخ ساختاریافته اعتبارسنجی می‌شود: نوع ویجت، والد/فرزند، مختصات، چرخه‌ها و محدودهٔ استایل. مدل اجازهٔ اجرای HTML، JavaScript یا فرمان سیستم ندارد.
6. کانتینرهای قابل‌ویرایش و ویجت‌های بومی ساخته می‌شوند: **Heading، Text Editor، Button، Image، Icon خالی و Divider**. دکمه‌ها لینک خالی دارند؛ آیکن‌ها عمداً نماد انتخاب‌شده ندارند. فقط نواحی تشخیص‌داده‌شده به‌عنوان عکس برش می‌خورند، نه همهٔ اجزای صفحه.
7. ویرایشگر بصری خروجی باز می‌شود. با کلیک روی المان، محتوا/استایل/پیشرفته را تغییر دهید؛ JSON و CSS خروجی به‌روز می‌شوند. حذف/بازگشت، تغییر نوع، جابه‌جایی میان هم‌سطح‌ها و تغییر اندازه در breakpoint انتخاب‌شده حفظ شده‌اند.
8. برای اصلاح تشخیص، به تب تصویر برگردید. کادر المان یا نام آن را انتخاب کنید، نوع/متن/فونت/رنگ را اصلاح و سپس بازسازی کنید. بازسازی با تأیید شما **ویرایش دستی خروجی همان تصویر را جایگزین** می‌کند. کانتینر دارای فرزند را نمی‌توان بدون تغییر ساختار به ویجت تبدیل کرد.
9. JSON و CSS را با هم خروجی بگیرید. ZIP هر طرح، برش عکس‌ها در `images/`، ساختار تشخیص در `*.vision-layout.json` و HTML بازسازی‌شده در `*.reconstructed.html` را هم دارد.

فایل تحلیل و HTML بازسازی‌شده تصویرِ وضعیت آخرین ساخت از تشخیص‌اند؛ ویرایش‌های مستقیم بعدی در ویرایشگر خروجی فقط در قالب JSON/CSS اعمال می‌شوند، نه به‌صورت برگشتی در آن دو فایل.

حالت قدیمی برش سادهٔ تصویر همچنان **گزینه‌ای صریح و جدا** در تنظیمات تبدیل است. اگر مدل حاضر نباشد، پاسخ نامعتبر باشد یا تحلیل شکست بخورد، برنامه مخفیانه تصویر را برش نمی‌زند و آن را نتیجهٔ تشخیص Qwen معرفی نمی‌کند. «لغو» موتور را نیز متوقف می‌کند تا درخواست طولانی ادامه پیدا نکند.

## محدودیت‌ها و موارد بازبینی

- از یک تصویر نمی‌توان HTML اصلی، breakpointهای واقعی موبایل/تبلت، نام دقیق فونت، لینک‌ها، متن پنهان و رفتار تعاملی را بازیابی کرد. خروجی **بازسازی تقریبی** است، نه نسخهٔ پیکسل‌به‌پیکسل تضمین‌شده.
- مدل ممکن است متن، کادر، ترتیب، والد، رنگ یا نوع ویجت را اشتباه تشخیص دهد. نمایش کادرها برای بازبینی همین موارد است. اگر مدل همه‌چیز را عکس تشخیص دهد، متن قابل‌ویرایش کافی تولید نمی‌شود؛ باید تشخیص را اصلاح یا ورودی را ساده‌تر کنید.
- تبدیل کادرها به Flex، فاصله‌ها و padding تخمینی است؛ هم‌پوشانی، absolute، grid پیچیده، سایه‌ها و گرادیان‌های دقیق تضمین نمی‌شوند. فونت جایگزین Arial/Tahoma است. در موبایل ستون‌بندی پیشنهادی ساخته می‌شود؛ صحت آن را دستی بررسی کنید.
- پردازش مرحله‌ای است؛ ویجت‌ها بعد از آماده‌شدن و اعتبارسنجی تحلیل ساخته می‌شوند، نه از توکن‌های ناقص در حین تولید مدل.
- تصویر مرورگر در صورت نیاز کوچک می‌شود: عرض تا ۱۶۰۰، ارتفاع تا ۱۲۰۰۰ و حداکثر ۱۶ مگاپیکسل. ورودی سرویس حداکثر ۸ MB است. تصویر خیلی بلند به حداکثر ۸ قطعه تقسیم می‌شود؛ مرز برش ممکن است وسط یک المان بیفتد. هر قطعه برای مدل به حداکثر ۱۲۸۰×۱۵۳۶ محدود می‌شود؛ متن ریز ممکن است خوانده نشود.
- سقف مدل برای هر پاسخ ۴۰۹۶ توکن است؛ JSON ناقص یک بار با تعداد المان کمتر دوباره درخواست می‌شود. کل طرح حداکثر ۱۶۰ گره دارد. تصاویر شلوغ/بلند را به سکشن‌های کوچک‌تر تقسیم کنید. هم‌زمان یک تحلیل اجرا می‌شود.
- زمینهٔ مدل بینایی ۸۱۹۲ توکن، یک slot و تصویر تا ۱۵۳۶ توکن درخواست می‌شود. این محدودیت‌ها تضمین مصرف حافظهٔ مشخص نیستند.
- عکس‌های برش‌خورده در پیش‌نمایش data URI دارند. وردپرس ممکن است آن‌ها را مستقیم وارد نکند؛ فایل‌های پوشهٔ `images` را در رسانه آپلود و URL ویجت‌های Image را جایگزین کنید. انتقال خودکار رسانه پیاده نشده است.
- آموزش micrograd قبلی همچنان یک دسته‌بند سبک کاربرآموز است؛ Qwen را فاین‌تیون نمی‌کند. مسیر بینایی جدید از مدل ازپیش‌آموزش‌دیدهٔ VL استفاده می‌کند.
- پیش‌نمایش، ویرایشگر خود برنامه است؛ تست نهایی در WordPress/Elementor staging لازم است. ایمپورت زندهٔ وردپرس در این محیط بررسی نشده است.

## آزمون‌های انجام‌شده و مرز ادعا

- قرارداد backend با پاسخ **آزمایشی صریح**: ساختار امن، چرخه/والد/شناسه/NaN/کادر نامعتبر، ارسال تصویر واقعی و schema، لغو، سقف توکن و قطعه‌بندی تصویر بلند.
- مرورگر با endpointهای job شبیه‌سازی‌شده: بارگذاری تصویر → ساخت ۷ ویجت بومی و ۷ کانتینر، بدون HTML fallback؛ ابعاد دکمه، ویرایش زنده و JSON، آیکن خالی، موبایل ۳۷۵ بدون سرریز در نمونه، اصلاح نوع و بازسازی و محتویات ZIP. این **تست دقت تشخیص مدل نیست**.
- تست واقعی موتور چندوجهی با **SmolVLM-256M Q8 + projector Q8 روی Linux CPU و llama.cpp b11095**: دریافت تصویر دایرهٔ سبز از API و پاسخ JSON با `color: green`. این تست فقط مسیر واقعی تصویر و خروجی مقید را می‌سنجد؛ اثبات کیفیت Qwen یا بازسازی صفحه نیست.
- تست‌های قبلی ویرایش/درگ/تغییر نوع، دسته‌بند واقعی micrograd و inference متنی Qwen2.5-0.5B دوباره اجرا شدند.
- **مدل پیشنهادی Qwen3-VL-4B، اجرای EXE روی Windows، شتاب‌دهی RTX/CUDA، دقت OCR فارسی و ایمپورت زندهٔ Elementor در این محیط تست نشده‌اند.** تصویر واقعی از طرح شما نیز هنوز دریافت نشده است.

گزارش‌ها در ریشهٔ بسته و سورس آزمون‌ها در `source/tests/` قرار دارند. گزارش‌های نسخه‌های قبلی برای قابلیت‌های قبلی‌اند؛ برای دامنهٔ بینایی به گزارش‌های ۱.۷ مراجعه کنید.
