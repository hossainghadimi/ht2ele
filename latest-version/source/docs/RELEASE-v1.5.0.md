# HTML2Elementor 1.5.0

## روند جدید: ابتدا ورودی را ببینید و اصلاح کنید

1. HTML و CSSهای وابسته را اضافه کنید؛ برنامه **قبل از تبدیل** تب «پیش‌نمایش و اصلاح ورودی» را باز می‌کند. دکمه «نمونه» نیز اکنون فقط نمونه را بارگذاری می‌کند، نه اینکه فوراً تبدیل کند.
2. ورودی در iframe مرورگر مستقل نمایش داده می‌شود. عرض واقعی را روی ۱۲۰۰، ۷۶۸، ۳۷۵ یا مقدار دلخواه ۲۴۰ تا ۲۵۶۰ پیکسل بگذارید؛ media query به عرض خود این صفحه واکنش نشان می‌دهد.
3. روی المان کلیک کنید. می‌توانید نوع خروجی را دستی تعیین کنید: خودکار، کانتینر، تیتر، متن، دکمه، آیکن خالی، تصویر، HTML یا نادیده گرفتن. «انتخاب والد» برای انتخاب ظرف یک المان است.
4. متنِ المان بدون فرزند، لینک و CSSهای margin/padding/gap/border/font-size/width/display/flex-direction قابل ویرایش‌اند. برای المان دارای فرزند، ویرایش مستقیم HTML داخلی جداگانه در دسترس است تا ویرایش متن ناخواسته فرزندان را حذف نکند.
5. استایل‌ها را برای همه اندازه‌ها، فقط تبلت یا فقط موبایل اعمال کنید. مقادیر CSS باید معتبر و همراه واحد لازم باشند؛ مقدار خالی یعنی «بدون تغییر».
6. «بازگشت تغییر ورودی» آخرین ویرایش همان فایل را برمی‌گرداند. فایل اصلی روی دیسک تغییر نمی‌کند؛ ویرایش روی نسخه کاری داخل مرورگر است. با بارگذاری مجدد صفحه، فایل‌ها باید دوباره وارد شوند.
7. «تبدیل همین ورودی‌ها» را بزنید. نوعی که دستی تعیین کرده‌اید، در حالت ترکیبی/بومی بر تشخیص خودکار اولویت دارد.

اگر ورودی را پس از تبدیل ویرایش کنید، خروجی قبلی از رابط پاک می‌شود تا خروجی قدیمی را اشتباهی دانلود نکنید؛ دوباره تبدیل را بزنید.

## تغییر نوع ویجت پس از تبدیل

در تب ویرایش خروجی، یک ویجت را انتخاب کنید. بالای پنل، بخش «تغییر نوع ویجت» اضافه شده است:

- متن → دکمه، همراه انتقال متن، لینک موجود، تایپوگرافی و تنظیمات مشترک فاصله/حاشیه.
- HTML → آیکن **خالی**؛ کد HTML با ویجت آیکن بومی جایگزین می‌شود، بدون انتخاب خودکار نماد.
- تیتر، متن، دکمه، آیکن، HTML و تصویر به‌عنوان مقصدهای تغییر نوع در دسترس‌اند.
- تصویر بدون URL مشخص نیازمند واردکردن دستی آدرس تصویر است؛ محتوای تصویری از متن حدس زده نمی‌شود.
- شناسه ویجت حفظ می‌شود و JSON، clipboard و شمارش ویجت‌ها همگام می‌شوند.
- «بازگشت تغییر نوع» نوع و تنظیمات قبلی را بازیابی می‌کند. تاریخچه فقط برای جلسه جاری مرورگر است.
- برای جلوگیری از حذف ساختار، تغییر نوع ویجت دارای `elements` فرزند محدود شده است؛ ویجت داخلی را انتخاب کنید. کانتینرها به‌عنوان ویجت متنی تبدیل نمی‌شوند.

تغییر نوع ساختار محتوا را تغییر می‌دهد؛ انتظار نداشته باشید یک فرم عملیاتی یا جدول پیچیده با تبدیل به دکمه، همان عملکرد قبلی را حفظ کند. بازگشت تغییر برای همین منظور فراهم شده است.

## اصلاحات تشخیص و آیکن

- SVGهای کوچک با viewBox آیکنی حتی بدون کلاس `icon` شناسایی می‌شوند؛ پشتیبانی از الگوهای رایج Remix/Bootstrap/Iconify و `data-icon` گسترش یافته است.
- وجود SVG/آیکن داخل پاراگراف، تیتر یا منو دیگر کل والد را بی‌دلیل وارد HTML نمی‌کند؛ ویجت‌های داخلی پیمایش می‌شوند.
- خروجی آیکن بومی همچنان `selected_icon: {value:"",library:""}` دارد. در المنتور آیکن دلخواه را دستی انتخاب کنید.
- گرافیک SVG بزرگ و غیرآیکنی می‌تواند تصویر SVG شود، نه HTML. تصویر SVG داده‌ای ممکن است در سایت مقصد نیازمند بارگذاری مجاز در رسانه باشد.
- انتخاب دستی HTML در ورودی، یا انتخاب حالت «کل صفحه HTML»، عمداً محترم است و آیکن درون آن به‌اجبار جدا نمی‌شود. برای تبدیل بومی، حالت ترکیبی/بومی را استفاده کنید.
- تشخیص خودکار برای همه نمادهای ساخته‌شده صرفاً با CSS یا تصاویر مبهم تضمین‌شده نیست؛ همین‌جا می‌توانید با انتخاب دستی «آیکن خالی» تشخیص را اصلاح کنید.

## اصلاحات فاصله و ریسپانسیو

- ترتیب `<link>` و `<style>` در ورودی حفظ می‌شود. قبلاً استایل‌های خارجی پس از همه استایل‌های داخلی قرار می‌گرفتند و ممکن بود نتیجه cascade برعکس ورودی شود.
- ویژگی `media` روی link/style حفظ می‌شود.
- specificity استاندارد سلکتورها و `!important` برای نگهداری مقادیر نسبیِ اعلام‌شده در CSS لحاظ می‌شوند؛ محاسبه نهایی همچنان به مرورگر سپرده می‌شود. کتابخانه MIT همراه برنامه و آفلاین است.
- `box-sizing` محاسبه‌شده حفظ می‌شود. پدینگ و border هنگام انتقال عرض بلوک‌های content-box به ساختار المنتور دیگر از عرض محتوا کم یا به آن اضافه نمی‌شوند.
- پیش‌نمایش خروجی به iframe واقعی منتقل شده است. CSS دیگر نسبت به عرض کل رابط برنامه ارزیابی نمی‌شود. عرض‌های خروجی ۱۲۰۰/۷۶۸/۳۷۵ پیکسل‌اند؛ صفحه داخل iframe اسکرول مستقل دارد و در فضای باریک، اسکرول افقی بوم برای دیدن کل عرض واقعی وجود دارد.
- بلوک‌های معمولی فقط در پیش‌نمایش به Flex اجباری تبدیل نمی‌شوند؛ جریان بلوکی و رفتار فاصله‌های آن حفظ می‌شود. گروه متن و آیکن به‌صورت گروه افقی نگاشت می‌شود.
- لایه‌های داخلی اضافه‌شده برای رندر ویجت، margin/padding/border مصنوعی نمی‌گیرند.
- لیست کاملی که داخل text-editor حفظ می‌شود، فاصله‌های اصلی را یک بار از HTML خودش می‌گیرد، نه یک بار دیگر از wrapper.

## آزمون‌های انجام‌شده

`tests/test_v150.py` و `tests/report-v1.5.0.json`:
- نمایش و ویرایش ورودی پیش از ایجاد خروجی؛ تشخیص دستی نوع، متن و لینک.
- ویرایش فاصله فقط موبایل و بازگشت ویرایش ورودی.
- ترتیب فایل CSS/استایل داخلی و اولویت درصد عرض با !important.
- شناسایی SVG عمومی کوچک، آیکن داخل منو/پاراگراف و آیکن Remix.
- مقایسه x/y/width/height سه المان در HTML اصلی و خروجی در viewportهای واقعی ۱۲۰۰، ۷۶۸ و ۳۷۵؛ تطابق در نمونه تست با آستانه ۱٫۱ پیکسل.
- تغییر نوع متن→دکمه و HTML→آیکن، بازگشت کامل و همگام‌سازی JSON/clipboard.
- حفظ اسکریپت در خروجی بدون اجرای آن در پیش‌نمایش ورودی یا خروجی؛ اسکرول صفحه iframe.

آزمون‌های بازگشت نسخه‌های قبل (`browser_test.py` و `test_v140.py`) برای iframe جدید به‌روز شده‌اند. تست مسیر دانلود و ترتیب نسخه با `go test ./...` انجام می‌شود.

## محدودیت‌ها و نصب

- فایل مشکل‌دار کاربر در این نوبت در دسترس نبود؛ نتیجه با نمونه‌های تست بررسی شده است، نه با فایل مشخص کاربر. برای بررسی اختلاف باقی‌مانده، همان HTML و همه CSSهای وابسته باید ارائه شوند.
- بوم، اجرای واقعی Elementor/WordPress نیست. تضمین پیکسل‌به‌پیکسل برای هر HTML، افزونه یا طرح دلخواه وجود ندارد. آزمون ایمپورت واقعی در وردپرس و اجرای EXE در ویندوز در این محیط انجام نشده است.
- **JSON و CSS همراه باید با هم در سایت استفاده شوند.** CSS مکمل برای media queryهای سفارشی و کنترل‌هایی که معادل بومی ندارند لازم است. پس از تغییر طراحی در Elementor، قواعد CSS مکمل را هم بررسی کنید.
- اندازه‌گیری فونت خارجی بدون فایل/دسترسی مناسب نمی‌تواند متریک دقیق آن فونت را تضمین کند. CSS لینک‌شده پیدا نشده در پیش‌نمایش ورودی اعلام می‌شود؛ آن را همراه HTML وارد کنید.
- breakpointهای معمول min/max-width پشتیبانی می‌شوند؛ container query، CSS لایه‌ای پیچیده، layout ایجادشده با JavaScript، واکنش به hover/orientation و قواعد پیچیده ممکن است اصلاح دستی بخواهند.
- اسکریپت‌ها برای امنیت در هیچ‌کدام از دو پیش‌نمایش اجرا نمی‌شوند، اما در HTML خروجی حفظ می‌شوند.
- ورودی تصویر پیش‌نمایش دارد، ولی ویرایش معنایی ویجت‌ها قبل از تبدیل آن وجود ندارد. OCR اضافه نشده؛ خروجی تصویر همچنان مبتنی بر قطعات تصویری است.

بسته: `versions/HTML2Elementor-Windows-v1.5.0.zip` برای Windows 10/11 x64. نسخه قبلی را ببندید، ZIP را استخراج و `HTML2Elementor.exe` را اجرا کنید. ZIPهای قبلی بازنویسی نشده‌اند. آرشیو تجمیعی جدید شامل همه بسته‌های مستقل موجود است.
