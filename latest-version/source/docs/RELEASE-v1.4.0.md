# HTML2Elementor 1.4.0 — ریسپانسیو، آیکن خالی و فاصله‌های ورودی

## تغییرات این نسخه

### خروجی ریسپانسیو
- اندازه فونت، جهت Flex، ستون‌های Grid، gap، padding/margin، ضخامت border و شعاع گوشه برای دسکتاپ، تبلت و موبایل در تنظیمات native ذخیره می‌شوند.
- مقادیر صفر موبایل صریح نوشته می‌شوند؛ فاصله یا border دسکتاپ به‌اشتباه به موبایل منتقل نمی‌شود.
- عرضی که فقط در دسکتاپ تعریف شده است می‌تواند در دستگاه کوچک به auto بازگردد.
- اجزایی که فقط در موبایل یا تبلت ظاهر می‌شوند دیگر در مرحله تبدیل حذف نمی‌شوند.
- مرزهای متفاوت media query ورودی، مثل ۹۰۰ و ۶۰۰ پیکسل، برای استایل‌های قابل‌نگاشت با CSS اختصاصیِ المان‌های خروجی بازسازی می‌شوند؛ صرفاً به مرز ۱۰۲۴/۷۶۷ المنتور کشیده نمی‌شوند.
- درصدها و ترکیب px/% و margin:auto حفظ می‌شوند؛ بلوک‌های عادی با margin:auto در کانتینر المنتور بی‌دلیل جمع نمی‌شوند.

### آیکن‌ها
- آیکن‌های قابل‌شناسایی به `widgetType: icon` با `selected_icon: { value: "", library: "" }` و کلید قدیمی icon خالی تبدیل می‌شوند.
- هیچ آیکن Font Awesome یا تصویر SVG به‌صورت خودکار برای این ویجت‌ها انتخاب نمی‌شود.
- اندازه، رنگ، فاصله و border ویجت باقی می‌مانند تا انتخاب دستی بعدی آسان باشد.
- گروه‌های اجتماعی، لیست‌ها و جعبه‌های دارای آیکن به کانتینر و آیکن‌های مجزای قابل‌ویرایش تبدیل می‌شوند؛ آیکن در یک social-icons/icon-list خودکار محبوس نمی‌شود.
- آیکن داخل دکمه، اگر شناسایی شود، از متن حذف و انتخاب آیکن دکمه خالی می‌شود؛ دکمه همچنان یک ویجت بومی مستقل است.
- کادر «آیکن خالی» فقط راهنمای بوم نرم‌افزار است و در قالب JSON یا CSS سایت صادر نمی‌شود. در المنتور از پنل آیکن، نماد دلخواه را انتخاب کنید.
- انتخاب دستی کلاس آیکن در پنل نرم‌افزار نیز library مناسب را در JSON ثبت می‌کند.

### دکمه‌ها
- button، input با نوع button/submit/reset، لینک‌های دارای کلاس دکمه، role=button و data-h2e-widget=button پیش از مسیر HTML پیچیده بررسی می‌شوند.
- وجود SVG یا آیکن در دکمه باعث تبدیل کل دکمه به HTML نمی‌شود.
- متن، لینک، رنگ، پدینگ داخلی، مارجین بیرونی، border و گوشه‌ها به تنظیمات مربوط به دکمه منتقل می‌شوند.
- ساختار فرم‌های کامل همچنان به HTML سپرده می‌شود؛ تبدیل کنترل‌های ارسال درون فرم به لینک بومی نباید عملکرد ارسال فرم را بشکند. بازسازی فرم عملیاتی Pro یا اسکریپت‌های کلیک جزو این نسخه نیست.

### Border و فاصله‌ها
- border-width چهار ضلع و border-radius چهار گوشه جداگانه خوانده می‌شوند.
- حاشیه ویجت‌های عادی با کلیدهای Advanced دارای پیشوند `_` ذخیره می‌شود؛ دکمه و تصویر کنترل اختصاصی خود را دارند.
- borderهای دارای رنگ/سبک متفاوت در اضلاع یا گوشه‌های بیضوی از طریق CSS همراه حفظ می‌شوند.
- padding داخلی دکمه روی wrapper دوباره اعمال نمی‌شود.
- ویرایش پدینگ موبایل در بوم، پدینگ دسکتاپ را تغییر نمی‌دهد.

## روش استفاده

1. نسخه قبلی را ببندید و ZIP جدید را استخراج کنید.
2. `HTML2Elementor.exe` را اجرا کنید؛ نصب Python لازم نیست.
3. HTML و CSSهای مربوط را وارد کنید. حالت **ترکیبی** یا **ویجت‌های بومی** و چیدمان **Container جدید** توصیه می‌شود.
4. پیش‌نمایش دسکتاپ/تبلت/موبایل را بررسی کنید و از پنل هر المان آن را ویرایش کنید.
5. **JSON و CSS همراه آن هر دو** در سایت مقصد استفاده شوند. برای تغییر استایل‌های پیچیده یا قواعد نقاط شکست سفارشی، CSS خروجی را نیز بررسی/ویرایش کنید.
6. در المنتور آیکن‌های خالی را از ناوبری انتخاب و نماد دلخواه را تعیین کنید.

حالت «کل صفحه داخل HTML» عمداً همه محتوا را در HTML نگه می‌دارد و تبدیل به ویجت بومی انجام نمی‌دهد.

## دامنه و محدودیت‌ها

- نگاشت native بر اساس نمونه‌های دسکتاپ ۱۲۰۰، تبلت ۷۶۸ و موبایل ۳۷۵ پیکسل انجام می‌شود. CSS مکمل مرزهای ساده min/max-width با واحدهای px/em/rem را تا ۲۴ مرز و کمتر از ۵۰۰۰ پیکسل تحلیل می‌کند.
- ورودی بدون CSS ریسپانسیو، طراحی موبایل جدید دریافت نمی‌کند؛ هدف حفظ رفتار ورودی است، نه حدس‌زدن طراحی دیگری.
- container queries، قواعد پیچیده orientation/interaction، انیمیشن‌ها، CSS ایجادشده توسط JavaScript و typography سیال بسیار پیچیده ممکن است به اصلاح دستی نیاز داشته باشند. CSS اصلی حذف نمی‌شود؛ تطابق پیکسل‌به‌پیکسل برای هر HTML دلخواه تضمین نشده است.
- آیکن‌های ناشناخته یا تزئینات صرفاً CSS و تصویرهای مبهم لزوماً قابل‌شناسایی نیستند. SVGهای بزرگ و گرافیک‌های عمومی بدون نشانه آیکن در HTML حفظ می‌شوند. تشخیص آیکن در پیکسل‌های تصویر وجود ندارد.
- فرم کامل و ویجت‌های وابسته به منطق وردپرس/Pro همچنان HTML fallback دارند. آیکن‌های جاسازی‌شده در چنین HTMLهای پیچیده، مشمول تبدیل تک‌ویجتی نیستند.
- استفاده از فونت‌ها و تصاویر سفارشی در سایت مقصد نیازمند در دسترس بودن فایل‌های آن‌هاست.
- اسکریپت ورودی در HTML خروجی حفظ می‌شود، ولی در بوم زنده اجرا نمی‌شود.
- ورودی تصویر همچنان خروجی مبتنی بر قطعات تصویری دارد؛ OCR یا بازسازی متن/آیکن بومی از تصویر اضافه نشده است.

## آزمون‌ها

- `tests/test_v140.py`: آیکن‌های خالی FA/Material/Bootstrap/SVG و اجتماعی/لیست؛ دکمه‌های button/role/input/link/SVG؛ فاصله‌ها و border موبایل؛ auto و واحدهای مختلط؛ محتوای فقط موبایل؛ انتخاب دستی آیکن؛ استقلال ویرایش موبایل؛ اسکرول.
- همین آزمون CSS صادرشده را در عرض‌های ۱۱۰۰، ۹۵۰، ۸۵۰، ۶۵۰ و ۵۰۰ پیکسل با استایل بومی شبیه‌سازی‌شده بررسی می‌کند تا مرزهای ورودی ۹۰۰ و ۶۰۰ پیکسل رعایت شوند.
- `tests/browser_test.py`: آزمون بازگشت قابلیت‌های قبلی، ویرایش JSON، repeater، ورودی تصویر و حفظ اسکریپت.
- `go test ./...`: مسیرهای دانلود نسخه، ترتیب عددی نسخه‌ها و HEAD بدون بدنه.
- گزارش جدید در `tests/report-v1.4.0.json` است.

EXE برای Windows 10/11 x64 ساخته شده است. در این محیط تست اجرا روی ویندوز و ایمپورت در WordPress/Elementor واقعی انجام نشده؛ قالب را ابتدا در سایت آزمایشی وارد کنید.

## نسخه‌ها

بسته جدید با نام مستقل `HTML2Elementor-Windows-v1.4.0.zip` در `versions` ذخیره می‌شود. هیچ ZIP قدیمی بازنویسی نشده است. آرشیو تجمیعی جدید شامل بسته‌های مستقل موجود، از جمله ۱.۳.۰ و ۱.۴.۰ است؛ آرشیو تجمیعی قبلی نیز جداگانه حفظ می‌شود.
