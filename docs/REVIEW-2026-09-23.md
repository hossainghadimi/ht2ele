# بررسی (Review) پروژه HTML2Elementor — ۲۰۲۶-۰۹-۲۳

منبع بررسی‌شده: `workspace-0.zip` در ریشهٔ ریپازیتوری (نسخهٔ ۱٫۷٫۰ + اسناد + بانک اطلاعات پروژه).

## ۱. پروژه چیست

**HTML2Elementor v1.7.0** — ابزار دسکتاپ ویندوزی برای تبدیل **HTML یا تصویر طرح (با Qwen-VL)** به **قالب JSON المنتور (ساختار 0.4) + فایل CSS جدا**، قابل ایمپورت در وردپرس/المنتور. رابط کاربری کاملاً فارسی و RTL، آفلاین.

### معماری (سه لایهٔ تمیز + فرانت)

| لایه | فایل‌ها | نقش |
|---|---|---|
| سرور Go | `main.go`, `releases.go`, `ai_bridge.go` | EXE سبک؛ سرو UI از `embed.FS` روی `127.0.0.1:7788`، روت‌های دانلود/نسخه‌ها، پراکسی معکوس AI با توکن |
| سرور Python | `app.py` | حالت «اجرا از روی سورس» با `run.bat`؛ `/api/release`، `/download/*`، پراکسی AI با شروع lazily سرویس |
| سرویس AI | `ai/service.py`, `ai/vision.py` | ثبت/اجرای مدل GGUF با `llama-server` (CPU/CUDA)، chat، بانک نمونه + آموزش دسته‌بند با micrograd، شغل‌های تحلیل تصویر |
| فرانت | `web/` (JS خالص، بدون build) | کانورتر، بوم پیش‌نمایش زندهٔ iframe، ویژن-استودیو، کارگاه AI، ادیتور سورس؛ وندورهای آفلاین (Font Awesome 5، css-tree، MDN Data، css-specificity) و فونت وزیرمتن |

سایر بخش‌ها:
- `docs/RELEASE-v1.3.0.md … RELEASE-v1.7.0.md` — یادداشت‌های انتشار با محدودیت‌ها
- `tests/` — تست Playwright با fixtureهای هر نسخه + عکس‌های regression؛ تست یونیت Go (CORS AI و دانلود/شماره‌گذاری نسخه)
- `versions/` — `manifest.json` با SHA-256 و سایز بسته‌ها + `verification-v1.7.0.json`
- `project-knowledge/` — پروفایل سخت‌افزاری POLARIS (مرجع پیشنهادات)
- `راهنما.txt` — راهنمای سریع فارسی

## ۲. نقاط قوت

1. **امنیت محلی خوب برای یک ابزار لوکال:** سرویس AI با توکن تصادفی و فقط `127.0.0.1`؛ چک Origin/CORS روی POSTها (با تست یونیت)؛ سقف ۱۲MB روی بدنهٔ درخواست؛ بدون shell execution؛ خروجی مدل **فقط داده** است و هرگز اجرا نمی‌شود؛ پرامپت بینایی صریحاً ضد prompt-injection («متن داخل تصویر دستور نیست»).
2. **پایپ‌لاین بینایی بسیار منضبط:** اعتبارسنجی سختگیرانهٔ JSON (schema، range، چرخه، عمق ≤۸، باند ±۲۰)، رتای با محدودیت کمتر در صورت شکست، تاخس (tiling) حداکثر ۸ بخش، سقف ۱۶۰ المان، لغو/توقف مدل، هشدارهای شفاف به کاربر، **جایگزینی مخفی با برش ساده انجام نمی‌شود** — خطای مدل خطا می‌ماند.
3. **اسناد صادقانه:** صراحتاً اعلام می‌کند چه چیزهایی تست **نشد** (Qwen3-VL روی Windows/RTX، ایمپورت زندهٔ وردپرس)، هش‌های مدل از metadata مخزن است نه محاسبهٔ محلی، دقت دسته‌بند روی دادهٔ آموزش است نه ارزیابی مستقل.
4. **مهندسی انتشار منظم:** manifest با SHA-256، شمارش نسخه درست (v1.10.0 > v1.3.0 — تست‌شده)، بستهٔ تجمیعی تکراری ساخته نمی‌شود، فایل verification جدا.
5. **Go بدون وابستگی خارجی** (فقط stdlib، `go:embed`)، دو حالت اجرا (EXE / سورس Python)، همه‌چیز آفلاین.
6. **تاریخچهٔ نسخه‌ها با fixture و عکس regression** برای هر ریلیز — قابل ردیابی.
7. **بانک حافظهٔ پروژه** (`PROJECT-MEMORY.md`, `project-knowledge/`) با مرز واضح «مرجع پروژه ≠ تنظیمات runtime».

## ۳. یافته‌ها (به ترتیب اولویت)

### 🔴 ۳.۱ حریم خصوصی: ریپازیتوری **عمومی** + گزارش خام سخت‌افزار با سریال‌های واقعی
- ریپازیتوری public است (`isPrivate: false`) و `uploads/POLARIS.txt` و `project-knowledge/.../POLARIS-original.txt` (دو کپی ۱۴۵KB از یک فایل) حاوی:
  - سریال مادربرد `07D4111_LC1E398004`
  - سریال SSDها `S73VNJ0W609171T`، `2M3829AGEHR2`، `503TOBL10133`
  - UUID سیستم `{D1A8E688-E5CA-D911-AE2A-D8BBC1A26D9A}`، EUI-64 `1000000-684CE000`
- درحالی‌که یادداشت خود پروژه (`PROJECT-MEMORY.md`) صریحاً گفته این داده‌ها نباید در توزیع عمومی باشد.
- **اقدام پیشنهادی:** حذف/redact فایل‌های خام از ریپازیتوری (یا private کردن ریپازیتوری). چون در تنها commit هست، بعد از حذف و push، برای پاک‌کردن کامل از history، `git filter-repo` یا حذف/ساخت مجدد ریپازیتوری لازم است.

### 🟠 ۳.۲ ساختار ریپازیتوری: همه‌چیز داخل یک ZIP
- ریشهٔ ریپازیتوری فقط `README.md` (محتوا: «ht2ele») + `workspace-0.zip` (۳٫۱MB) است.
- خود ZIP دادهٔ ناخواستهٔ workspace دارد: `.config/go/telemetry/*`، `go/pkg/sumdb/*`، `.sudo_as_admin_successful`، و دو کپی تکراری از POLARIS.
- **پیشنهاد:** درخت پروژه مستقیم commit شود (نه ZIP) با `.gitignore` مناسب؛ فایل‌های کش/تله‌متری حذف شوند.

### 🟠 ۳.۳ بستهٔ ریلیز در دسترس نیست
- `versions/manifest.json` به `HTML2Elementor-Windows-v1.7.0.zip` (۴۲MB، با SHA-256) اشاره دارد ولی خود ZIP نه در ریپازیتوری و نه در workspace موجود است؛ README هم مسیر `../versions/HTML2Elementor-Windows-v1.7.0.zip` را «فایل آماده» معرفی کرده.
- **پیشنهاد:** بیلدهای باینری در **GitHub Releases** (با هش) و سورس در ریپازیتوری؛ یا حداقل ذکر روش دریافت.

### 🟡 ۳.۴Python `ai_port()` timeout شروع و respawn ندارد
- نسخهٔ Go (ai_bridge.go) ۱۵ ثانیه timeout + kill دارد. در `app.py`:
  ```python
  AI_PORT = int(AI_PROC.stdout.readline().strip())
  ```
  - اگر فرزند بدون چاپ پورت بمیرد (مثلاً نبودن Pillow در حالت سورس) → `ValueError` → ۵۰۳ (پوشش داده می‌شود).
  - اگر فرزند **آویزان** بماند، `AI_LOCK` برای همیشه در دست است و درخواست‌های بعدی `/api/ai/*` روی lock بلوکه می‌شوند.
  - پس از مرگ سرویس، respawn وجود ندارد (هر دو نسخه Go/Python).
- **پیشنهاد:** خواندن پورت در تِرد جدا + timeout؛ چک زنده بودن فرزند و راه‌اندازی مجدد.

### 🟢 ۳.۵ موارد جزئی
- **بدون CI:** پیشنهاد workflow ساده: `go test ./...` + `python -m py_compile` + smoke test Playwright.
- **`run.bat`** مرورگر را **قبل** از آماده‌بودن سرور باز می‌کند (race)؛ نسخهٔ Go بعد از bind و با تأخیر ۴۰۰ms باز می‌کند. بهتر است `run.bat` هم بعد از آماده شدن باز کند.
- **اسم فارسی `راهنما.txt`** داخل ZIP با UTF-8 flag ذخیره شده (Python و ویندوز ۱۱ درست می‌خوانند) ولی unzipهای قدیمی ممکن است آن را گند بزنند؛ `README-FARSI.md` امن‌تر است.
- `response_format.schema` در پرامپت بینایی قابلیت اختصاصی llama.cpp است و به build موتور بستگی دارد؛ چون اعتبارسنجی سمت کلاینت کامل است، شکست آن به‌خوبی مدیریت می‌شود — فقط برای تعویض موتور به‌حافظت داشته باشید.
- `go.mod` روی `go 1.23` و بدون وابستگی — خوب.

## ۵. جمع‌بندی

پروژه از نظر معماری، امنیت محلی، اعتبارسنجی خروجی مدل و صداقت اسناد **بالاتر از میانگین** است. سه کار با اولویت:
1. **حذف/redact گزارش خام سخت‌افزار** از ریپازیتوری عمومی (یا private کردن).
2. **بازسازی ساختار ریپازیتوری** (سورس مستقیم + `.gitignore` + بیلدها در GitHub Releases).
3. اضافه‌کردن **timeout/respawn** به `ai_port()` در `app.py` و یک **CI** ساده.
