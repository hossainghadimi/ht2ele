# گزارش پیاده‌سازی نسخه ۱.۸.۰ — HTML2Elementor

تاریخ: ۲۰۲۶-۰۹-۲۴ · شاخه: `arena/01a0cfe3-ht2ele` · محل کد: `latest-version/source/`

## خلاصه

به درخواست شما، نسخهٔ ۱.۸.۰ روی کد `latest-version/source` پیاده شد:

1. **پایش تصویر بهتر با مدل‌های مناسب سیستم**: توصیه‌های مشخص برای سخت‌افزار مشابه POLARIS (RTX 3050 8GB + 32GB RAM) — `Qwen3-VL-8B-Instruct Q4_K_M + mmproj` (دقت بالاتر، حالت hybrid) و `Qwen3-VL-4B-Instruct Q4_K_M + mmproj Q8_0` (سریع‌تر) با لینک مخزن رسمی Hugging Face داخل برنامه.
2. **امپورت مدل در نرم‌افزار**: سه روش در «کارگاه AI» — ثبت مسیر (مانند قبل)، **اسکن دیسک** (پوشه‌های رایج؛ تعداد لایهٔ واقعی هر GGUF از متادیتای خود فایل خوانده می‌شود؛ جفت‌سازی خودکار mmproj هم‌خانواده)، و **ایمپورت مستقیم فایل** تا 8MB.
3. **استفادهٔ هم‌زمان GPU و CPU**: حالت جدید `hybrid` — موتور CUDA با `-ngl` محدود؛ لایه‌های offload‌شده روی GPU و ماست روی CPU **هم‌زمان** اجرا می‌شوند. مقدار ngl پیش‌فرض خودکار است (تعداد لایه از GGUF + تخمین VRAM) و در برنامه قابل تنظیم است.
4. **دقت بالای بینایی**: مدل ۸B در hybrid دقیق‌تر از ۴B است؛ برای چت‌باکس‌ها مدل متنی جدا (بدون mmproj) روی CPU کافی است و نیازی به فعال بودن مدل بینایی ندارد.
5. **دو بخش جداگانه با چت‌باکس در هر بخش**:
   - **مرحلهٔ ۱ — تصویر به HTML**: بعد از تحلیل، **HTML بازسازی‌شده** نمایش داده می‌شود؛ چت‌باکس AI (چندگام) تغییرات را اعمال می‌کند — همیشه با **پیش‌نمایش قبل از تأیید** — یا کادر کد مستقیم. دکمهٔ **«تأیید نهایی»** HTML را به مرحلهٔ ۲ می‌فرستد.
   - **مرحلهٔ ۲ — HTML به المنتور**: HTML تاییدشده در بوم ورودی می‌آید؛ **چت‌باکس این تب** اصلاحات نهایی را انجام می‌دهد (Undo در بوم حفظ است)؛ سپس «تبدیل به المنتور» → JSON + CSS.

## نتایج تست (محیط این کار — لینوکس)

- **E2E سرویس AI با موتور شبیه‌ساز: ۱۵/۱۵ پاس** — اسکن (خواندن ۳۶ لایه از GGUF)، ایمپورت + رد سرآیند نامعتبر، ثبت با mmproj، شروع hybrid با `-ngl 36` (آگومان‌های دقیق موتور ثبت و تأیید شد)، چت (ساده/چندگام/HTML-ویرایش/رد ورودی نامعتبر)، کل مسیر `vision/analyze`، توقف.
- **یونیت `extractHTML` (Node): ۶/۶ پاس**.
- **رگرسیون**: `test_vision_v170.py` (کنترکت بک‌اند بینایی) پاس؛ `test_ai_v160.py` (یکپارچگی کارگاه AI) پاس؛ `py_compile` و `node --check` همهٔ فایل‌ها پاک.
- **Go**: بلافاصله بازسازی نشده (ابزار go در این محیط نیست) — فقط تغییر ثابت `version` است؛ در بیلد ویندوزی خودتان با `build-windows.bat` ساخته و آزمون‌پذیر است.

## صادقانه: چه چیزی اینجا تست **نشده** است

- اجرای واقعی Qwen3-VL 4B/8B روی ویندوز/RTX 3050 (نیازمند سخت‌افزار شما).
- هم‌زمانی واقعی GPU+CPU در llama.cpp (منطق `hybrid` = همان مکانیزم رسمی `-ngl` بخش‌بندی‌شده؛ آگومان‌ها تأیید شده، اما مصرف واقعی VRAM/RAM و سرعت، روی سخت‌افزار شما سنجیده می‌شود).
- ایمپورت زندهٔ وردپرس.

## نکات راه‌اندازی برای سیستم شما

- چت‌باکس‌ها: یک مدل متنی (مثلاً Qwen3-4B-Instruct Q4_K_M) کافی است — روی CPU هم روان است.
- بینایی: Qwen3-VL-8B + mmproj را دانلود کنید، در «کارگاه AI» اسکن بزنید و با hybrid اجرا کنید؛ اگر VRAM کم بود، نوار ngl/VRAM را پایین بیاورید.
- موتور `engine-cuda` برای hybrid/CUDA لازم است (همان llama.cpp رسمی)؛ بدون آن، cpu خراب نمی‌شود فقط حالت hybrid خطای راهنما می‌دهد.
